DAY 06 — UDEMY GIT 19–22

GIT 19 · MERGE CONFLICT

Когда возникает конфликт:
Когда Git не может автоматически объединить изменения из двух веток, например когда в одном и том же месте файла были разные изменения.

git merge feature3 — объединяет ветку feature3 с текущей веткой.

git diff feature3 — показывает различия между текущей веткой и feature3.

<<<<<<< HEAD … ======= … >>>>>>> feature3
Верхняя часть — наши изменения из текущей ветки.
Нижняя часть — изменения из feature3.

git add . — добавляет исправленные файлы в staging area и отмечает конфликт решённым.

git commit — завершает merge, создавая коммит объединения.

git merge --abort — отменяет незавершённое слияние.

git pull origin main — получает изменения из удалённой ветки main и объединяет их с текущей веткой.

git config pull.rebase false — настраивает pull использовать merge.
true — настраивает pull использовать rebase.

Ловушка:
Если забыть удалить маркеры конфликта, они останутся в файле как обычный текст и попадут в коммит.


GIT 20 · TIME TRAVEL

git log — показывает историю коммитов проекта.

git checkout <хеш> — переходит к определённому коммиту (Detached HEAD).

git checkout -b lite-version / git switch -c lite-version — создаёт новую ветку lite-version от текущего коммита и переключается на неё.

git push origin lite-version — отправляет ветку lite-version на GitHub.

git switch main — переключается на ветку main.

Detached HEAD — это состояние, когда Git находится непосредственно на конкретном коммите, а не на ветке.

Если закоммитить в Detached HEAD и уйти без создания ветки, то коммит может стать недоступным при обычном просмотре истории и со временем быть удалён Git.


GIT 21 · STASH

Зачем нужен stash:
Чтобы временно сохранить незакоммиченные изменения и переключиться на другую задачу или ветку.

git stash — временно сохраняет изменения отслеживаемых файлов.

git stash list — показывает список всех сохранённых изменений.

git stash apply — возвращает изменения, но оставляет их в stash.

git stash pop — возвращает изменения и удаляет stash при успешном применении.

git stash drop — удаляет сохранение из stash.

git stash -u — сохраняет изменения вместе с новыми, ещё не отслеживаемыми файлами.

Какой тайник самый свежий:
stash@{0} — самое последнее сохранение.

Новые сохранения помещаются в начало списка.


GIT 22 · FORK

Fork — это копия чужого репозитория в твоём собственном аккаунте GitHub.

Fork отличается от clone тем, что:
Fork создаёт копию репозитория на GitHub в твоём аккаунте.
Clone скачивает репозиторий на твой компьютер.

Почему нельзя просто сделать push в чужой репозиторий:
Потому что у тебя обычно нет прав на запись в чужой репозиторий.

Как предложить свои изменения автору оригинала:
Нужно сделать Fork, клонировать свою копию, внести изменения, отправить их через Push и создать Pull Request в оригинальный репозиторий.




Merge — объединение веток.
Conflict — конфликт изменений.
Detached HEAD — нахождение непосредственно на коммите.
Stash — временное сохранение изменений.
Fork — копия чужого репозитория на GitHub.
Pull Request — предложение своих изменений автору оригинального репозитория.
