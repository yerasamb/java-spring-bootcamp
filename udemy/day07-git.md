ЧТО ТАКОЕ PULL REQUEST (СВОИМИ СЛОВАМИ)

Pull Request (PR) — это предложение объединить мои изменения кода с другой веткой или оригинальным репозиторием. Другие разработчики могут проверить код, оставить комментарии и одобрить изменения перед объединением.


ШАГИ ИЗ ВИДЕО (FORK → PR → MERGE)

1. TELUSKO — Fork на странице navinreddy20/quiz-app

Создаёт копию оригинального репозитория в своём аккаунте GitHub, чтобы работать со своим вариантом проекта.

2. TELUSKO — git clone <SSH-URL форка>

Скачивает свой Fork на компьютер, чтобы работать с проектом локально.

3. TELUSKO — изменил Controller.java

Вносит изменения в код, добавляя новую функциональность (comment).

4. TELUSKO — git status

Проверяет состояние проекта и видит, какие файлы были изменены.

5. TELUSKO — git add <файл>

Добавляет изменённый файл в staging area, подготавливая его к коммиту.

6. TELUSKO — git commit -m "comment added"

Сохраняет изменения в локальной истории Git с сообщением "comment added".

7. TELUSKO — git push origin main

Отправляет локальные коммиты в ветку main своего Fork на GitHub.

Изменения ушли в репозиторий TELUSKO, а не Navin'а. У Navin'а их ещё нет в оригинальном репозитории.

8. TELUSKO — Pull requests → New pull request

Открывает создание Pull Request, чтобы предложить Navin'у объединить изменения из своего Fork с оригинальным репозиторием.

9. TELUSKO — Create pull request + описание

Создаёт Pull Request и объясняет, какие изменения сделал и зачем.

Статус PR: Open (открыт). Изменения ещё не объединены.

10. Navin — открыл PR, посмотрел изменения

Проверяет изменённый код (Code Review), чтобы найти ошибки, оценить качество кода и решить, можно ли объединять изменения.

11. Navin — Merge pull request

Объединяет предложенные изменения с оригинальной веткой main.

После этого статус PR меняется с Open на Merged у обоих участников автоматически. Изменения становятся частью оригинального репозитория.


BASE И HEAD

base = репозиторий и ветка, КУДА мы хотим добавить изменения (оригинальный репозиторий Navin, main).

head = репозиторий и ветка, ОТКУДА мы берём изменения (Fork TELUSKO, main).

Если перепутать местами:
Git будет предлагать объединить изменения в неправильном направлении — например, из оригинального репозитория в Fork вместо Fork в оригинальный репозиторий.


ГДЕ ЖИВЁТ PR

PR живёт в оригинальном репозитории Navin, потому что именно туда TELUSKO предлагает добавить изменения.

TELUSKO видит тот же PR, потому что GitHub связывает PR с аккаунтами обоих участников и автоматически показывает обновления статуса.


PR БЕЗ ФОРКА (В КОМАНДЕ)

Pull Request можно создавать и без Fork, если у разработчика уже есть доступ к общему репозиторию.

Схема работы:

1. git switch -c feature-login
2. Изменяем код.
3. git add .
4. git commit -m "Add login feature"
5. git push origin feature-login
6. На GitHub создаём Pull Request: feature-login → main.
7. Команда проверяет код (Code Review).
8. После одобрения выполняется Merge.

Зачем это нужно:
Чтобы проверять код, обсуждать изменения, находить ошибки и не допускать попадания непроверенного кода в main.


МОЯ ОШИБКА В КВИЗЕ

Главное, что нужно запомнить:
- origin после clone указывает на репозиторий, который мы клонировали.
- git push origin main отправляет изменения в наш Fork, если мы клонировали именно Fork.
- Pull Request создаётся в репозитории, куда мы хотим добавить изменения.
- base — куда добавляем, head — откуда берём.
- Open означает, что PR ещё не объединён.
- Merged означает, что изменения успешно объединены.
- PR нужен не только для Fork, но и для обычной командной разработки.
